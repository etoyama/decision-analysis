# 見本: 判断の仰ぎ方を Decision Analysis にそろえる仕組みをどう作るか

チャットで判断を仰いだときの例。この plugin を作る前に、実際に行った判断を縮めた。

## Problem

- **課題1（事前）**: Claude が判断を仰ぐ最初の提示に、課題・比較軸・Must/Want の根拠がない。
  人間が「なぜこの観点で比べたのか」を聞き返すたびに、往復が1回増える。
- **課題2（事後）**: 出し直させるたびに、人間が形式を一から説明し直す必要がある。
- **前提にした事実**:
  - 配布しているテンプレート repo は、すでに外部 plugin に依存し、bootstrap スクリプトで導入を案内している（ADR を読んで確かめた）。
  - AskUserQuestion の直前に文脈を差し込む公式の hook はない（feature request を読んで確かめた）。
- **扱わない範囲**: 判断の中身の正しさ。この仕組みは、提示の形式だけを扱う。

## Criteria

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | どの repo の会話でも効く | Must | - | - | 課題1, 人間の発言 |
| M2 | 一言で出し直しを指示できる | Must | - | - | 課題2, 人間の発言 |
| M3 | 形式の正本が1か所 | Must | - | - | 正本を2か所に書かない原則 |
| W1 | 最初の提示で DA が出る | Want | 解決 | 高（人間） | 課題1 |
| W2 | テンプレートの配布先でも同じ形式が使える | Want | 費用 | 高（人間） | 人間の発言 |
| W3 | 作る手間と保守する手間 | Want | 費用 | 中（Claude の推測） | - |

## Options

- 何もしない
- A. グローバルの CLAUDE.md に、形式と発動条件を全部書く
- B. グローバルの skill を正本にし、CLAUDE.md には発動条件だけを書く
- C. B を plugin にする（skill と SessionStart hook）。配布先には導入を案内する

## Evaluation

| Must | 何もしない | A | B | C |
|---|---|---|---|---|
| M1 | 満たさない | 満たす | 満たす | 満たす |
| M2 | 満たさない | 満たす | 満たす | 満たす |
| M3 | - | 満たさない（配布先用にテンプレートへ写しが要る） | 満たさない（同左） | 満たす |

A と B は M3 で落ちる。Must を通るのは C だけなので、Want の表は比較ではなく、
C が各 Want をどこまで満たすかの確認になる。

| Want | C |
|---|---|
| W1 | SessionStart で発動条件が毎回入る。外すのは「当たるかどうか」の見極めで、そこは事後の手段で戻す |
| W2 | plugin を導入すれば、配布先でも同じ skill を使える |
| W3 | SKILL.md と見本と hook で3ファイル。repo を1つ増やす |

- **差がつく基準**: M3（A と B を落とした）。
- **感度**: W2 の重みが低い（自分の環境だけでいい）なら、M3 を写しなしで満たせるので B が残り、W3 で B が C に勝つ。

## Risks

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|
| A | 全 repo の全セッションで、形式の全文がコンテキストを食う | 形式を短く保つ |
| B | 配布先では形式が存在しない | テンプレートに写しを置く（M3 に反する） |
| C | 発動条件に当たる判断なのに、Claude が当たらないと見て黙って進む | 人間の聞き返しを発動条件に入れ、自動で出し直させる |

## Recommendation

C を推す。決め手は M3 で、配布先でも同じ形式を使うには、正本を plugin に置くしかない。

- 残るリスク: 発動条件の見極めを Claude が外す。機械的な検査（AskUserQuestion の hook）は、漏れる場所を観測してから足す。
- 決めてほしいこと: repo を public で作ってよいか。
