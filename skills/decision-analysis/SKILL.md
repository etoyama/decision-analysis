# Decision Analysis

人間に判断を仰ぐときの提示形式の正本。目的は、人間が**基準の立て方そのもの**に
質問できるようにすること（「なぜこの観点で比べたのか」「なぜこれが Must なのか」）。
そのために、すべての基準に出典を持たせ、重みを誰が決めたかを書く。

## いつ使うか

次のどれかに当たるとき。当たらないなら、推奨を1行で示して先へ進む。

- 選択肢が2つ以上あり、既存の決定（ADR / AC / 指示 / 原則）から一意に決まらない
- 決定を戻しにくい（公開契約、データ形式、外部に作るもの、ライブラリ選定、名前）
- 効果が今の作業の範囲を超える（ADR の候補）
- 人間が判断の理由を聞き返した
- 人間が「DA で」と頼んだ

## 出し直すとき

「DA で」と頼まれた、または理由を聞き返されたときの手順。

1. 直前の判断依頼を特定する。何を決めようとしていたかを1行で言い直す。
2. 確かめていない前提があれば、先に確かめる（ファイルを読む、コマンドを実行する）。
3. 足りない要素を継ぎ足すのではなく、下の形式で**全体を**書き直す。
4. 前回の提示から推奨が変わったら、その理由を最初に書く。

## 形式

チャットでも ADR でも同じ形式を使う。チャットでは本文に書き、最後に
AskUserQuestion などで選ばせる。

### 1. Problem

- **課題**: ID を振って列挙する（課題1、課題2…）。誰が困るか、放置するとどうなるか。
- **前提にした事実**: 比較の土台にした事実と、それを確かめた方法（読んだファイル、
  実行したコマンド、人間の発言）。確かめていないものは「未確認」と書く。
- **扱わない範囲**: この判断で解かないこと。

### 2. Criteria

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | … | Must | - | - | 課題1 |
| W1 | … | Want | 解決 | 高（人間） | 課題2 |
| W2 | … | Want | 費用 | 中（Claude の推測） | … |

- **Must**: 満たすか満たさないかの二択で判定でき、満たさない案はその場で却下してよいもの。
  程度で比べるものは、課題そのものでも Want に置く。
- **Want**: 程度で比べるもの。必ず次のどちらかに分類する。
  - **解決**: 課題をどれだけ解決できるか。どれかの課題 ID を出典に持つ。
  - **費用**: 解決にどれだけ費用がかかるか（時間・金・労力・読む人の負担・保守）。
  - どちらにも入らない基準は入れない。
- **出典**: 課題 ID / ADR / AC / 原則 / 人間の発言のどれか。出典がない基準は入れない。
- **重み**: 高 / 中 / 低。決めた人を必ず書く（人間 / Claude の推測）。
  Claude の推測の重みで結論が変わるなら、それを人間に聞く。
- **上限**: Must は3つ以下、Want は4つ以下。重要なものだけに絞る。

### 3. Options

- 1案1行で書く。「何もしない」を必ず入れる（今決める理由が分かる）。
- 「何もしない」を除いて4案以下。

### 4. Evaluation

1. **Must の表**: 各案が満たすか満たさないか。満たさないなら理由を短く書く。
2. **Want の表**: Must を通った案だけを比べる。セルは**文**で書く。点数の合計は出さない。
3. **差がつく基準**: 「差がつくのは Wn と Wm だけ」と明示する。全案で同じ評価の基準は判断に効かない。
4. **感度**: 「Wn の重みが X なら結論は Y に変わる」を1行で書く。変わらないなら「どの重みを動かしても変わらない」と書く。

### 5. Risks

推奨案だけでなく、比べた全案について書く。

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|

### 6. Recommendation

- 推奨案と決め手（差がつく基準のどれで決まったか）。
- 残るリスクと、この判断では塞がない穴。
- 人間に決めてほしいこと（Claude の推測の重み、未確認の前提）を最後に1つにまとめる。

### 7. Alternatives considered（ADR のみ）

評価の前に落とした案だけを、落とした理由と一緒に書く。比較の表に入れた案は書かない
（表とリスクの表で説明が済んでいる）。

## ADR に書くとき

ADR の節に次のように対応させる。

| ADR の節 | この形式 |
|---|---|
| `## Context` | 状況の説明と、Problem の「前提にした事実」 |
| `## Problem` | Problem の課題と扱わない範囲 |
| `## Decision Analysis` | Criteria、Options、Evaluation、Risks |
| `## Decision` | Recommendation のうち、決めたこと |
| `## Consequences` | Recommendation の残るリスクを含める |
| `## Alternatives considered` | 7 と同じ |

チャットでは Consequences と Related を省いてよい。Problem・Criteria・Evaluation は省かない。

## やってはいけないこと

- 点数の合計で決める（擬似精度になる。差がつく基準を文で比べる）。
- 出典のない基準や、解決にも費用にも入らない基準を入れる。
- 推奨案のリスクだけを書く。
- 確かめていない前提の上で比べる。
- AskUserQuestion の選択肢の説明だけで判断を渡す。
